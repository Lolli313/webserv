⚡ Stress & Performance Testing

Verify the server handles high load without crashing or blocking.

📋 Subject Requirements:

  • Availability: ≥ 99.5% under load
  • Non-blocking: Never hang indefinitely
  • Resilience: One request shouldn't stall others
  • Memory: No leaks during sustained load
  • Connections: Handle at least 1000 requests

🔧 Install Siege (if not installed):

# macOS brew install siege # Ubuntu/Debian sudo apt-get install siege # Verify installation siege --version

Test 1: Basic Load Test

Send 1000 requests with 25 concurrent users for 1 minute:

siege -c 25 -r 40 http://127.0.0.1:3000/

Expected: ✓ Availability > 99.5%

Test 2: Sustained Load

Run continuous load for 60 seconds with 50 concurrent users:

siege -c 50 -t60s http://127.0.0.1:3000/

Expected: ✓ No crashes, response time < 2s

Test 3: CGI Stress Test

Execute multiple CGI scripts simultaneously to test process management:

siege -c 15 -r 10 http://127.0.0.1:3000/cgi/script/python/test.py

Expected: ✓ All scripts execute (200), no zombie processes

Test 4: Mixed Operations

Test GET, POST, DELETE together with URLs file:

# 1. Create the urls.txt file printf "http://127.0.0.1:3000/\nhttp://127.0.0.1:3000/static/index.html\nhttp://127.0.0.1:3000/uploads/\nhttp://127.0.0.1:3000/cgi/script/python/test.py\n" > urls.txt # 2. Run the mixed test siege -c 25 -r 40 -f urls.txt

Expected: ✓ All routes respond correctly

Test 5: Connection Limit

Test with many concurrent connections:

siege -c 100 -r 10 http://127.0.0.1:3000/

Expected: ✓ Server doesn't crash, handles queue properly

✅ Pass Criteria:

  • Availability: ≥ 99.5% across all tests
  • No crashes: Server stays running throughout
  • No hangs: All requests complete or timeout gracefully
  • Error handling: Proper status codes on failures
  • Memory stable: No memory leaks (check with Valgrind)
  • Response time: Reasonable average (< 2s under normal load)

🐛 Debugging Performance Issues:

# Monitor server during stress test
htop  # Check CPU/memory usage

# Check for memory leaks
valgrind --leak-check=full ./webserv config.aero

# Monitor open connections
netstat -an | grep :3000 | wc -l

# Check file descriptors
lsof -p $(pgrep webserv) | wc -l
